# MacroPad for Apple Silicon

The Mac application uses the same MacroPad identity and interface as Windows:
`MacroPad.app`, executable `Contents/MacOS/MacroPad`, bundle identifier
`io.macropad.desktop`, and icon `MacroPad.icns`. Appearance names and upstream
author notices are not presented in the interface. Required notices travel in
`Contents/Resources/licenses` inside the application.

## Build on macOS

The packaging script must run on Darwin. It requires Rust/Cargo with the
`aarch64-apple-darwin` target, Xcode command-line tools, Python 3, and jq. It uses
the real Apple `plutil`, `codesign`, `lipo`, `otool`, `ditto`, and `hdiutil` tools.
It does not install or update the development environment.

From the `device` directory, supply the dependency-license JSON generated by
`cargo-bundle-licenses` for this source/build environment. The inventory must
include nonempty `third_party_libraries[].licenses[].text` entries with no
unresolved `NOT FOUND` notices. The companion manual build workflow prepares
this inventory before packaging.

```bash
export MACROPAD_DEPENDENCY_LICENSES_FILE="$PWD/dist/licenses/Rust-dependency-licenses.json"
export MACROPAD_ENABLE_SPARKLE=0
export MACROPAD_CREATE_APP_ZIP=1
./scripts/package-macos.sh "$PWD/dist" "$PWD/dist/inputs/keyboard-fw-0.10.1.bin"
```

The second argument is optional. When supplied, it must be a verified combined
firmware image for this keyboard. The script retains the established internal
`keyboard-fw.bin` filename and writes the image version and SHA-256 beside it.
Packaging does not flash a connected device.

The default is ARM64, even on an Intel Mac build host. Set
`MACROPAD_MACOS_ARCH=arm64` explicitly if desired; `aarch64` is equivalent.
`KEYBOARD_MACOS_ARCH` remains a fallback alias. An explicit `x86_64` requests an
Intel build. The script checks the produced Mach-O with `lipo` and rejects a
binary whose actual thin architecture does not match the requested package.
The minimum deployment target remains macOS 11.

For the current version, output is:

```text
dist/macos-aarch64/MacroPad.app
dist/MacroPad-0.15.0-macos-aarch64.dmg
dist/MacroPad-0.15.0-macos-aarch64.app.zip  # MACROPAD_CREATE_APP_ZIP=1
```

The DMG contains MacroPad.app and an Applications shortcut. The optional ZIP
uses `ditto --sequesterRsrc --keepParent`. Application resources contain the
upstream MIT notice, the Noto, Lucide and Simple Icons notices, and
`Rust-dependency-licenses.json`. Staging cleanup rejects symbolic links and
requires its resolved absolute target to remain inside the selected output.

## Signing and optional updates

Without signing credentials the script produces an **ad-hoc signed local
package**. A successful `codesign --verify` in this mode does not mean the app
is Developer ID signed or notarized. macOS distribution and Gatekeeper behavior
must not be described as verified until tested on a Mac.

For distribution signing, configure an existing Developer ID Application
identity through `MACROPAD_MACOS_SIGN_IDENTITY` or its existing
`MACOS_SIGN_IDENTITY` alias. The script accepts an exact certificate name or
hash and verifies that it is an available Developer ID Application identity.
`REQUIRE_SIGNING=1` refuses an unsigned build. An optional
`MACROPAD_NOTARY_PROFILE` selects an already configured notarytool keychain
profile; only then does the script submit, wait for acceptance, and staple the
application and DMG. It does not import credentials or create certificates.

Sparkle is absent from the normal build: no framework download, no link, no
feed URL, and no inherited public key. `MACROPAD_ENABLE_SPARKLE=0` forces this
state even if feed-related variables exist in the environment. With the default
`auto` mode, enabling Sparkle requires all of:

- Developer ID Application signing.
- Your own HTTPS `MACROPAD_SPARKLE_FEED_URL`.
- Your own valid 32-byte Ed25519 public key in `MACROPAD_SPARKLE_PUBLIC_ED_KEY`.
- A prepared framework distribution at `MACROPAD_SPARKLE_ROOT` (the older
  `KEYBOARD_SPARKLE_ROOT` alias is accepted).

The upstream public key is explicitly rejected. The script does not download a
framework even in this optional mode. It exports
`MACROPAD_SPARKLE_FRAMEWORK_DIR` only for the enabled build, signs nested helpers
before the framework and application, and verifies signatures. The Objective-C
bridge keeps its internal C ABI names while checking the MacroPad bundle
identity, opt-in plist flag, HTTPS feed, and decoded key length.

## Verification boundaries

Local Bash syntax and plist-template checks validate source packaging logic.
A real Mac build is still required to establish compilation, ARM64 output,
codesigning, and DMG integrity. Window rendering, permissions, launch-at-login,
USB communication, key actions, and firmware updating each require a separate
runtime check on macOS and, where relevant, a connected keyboard.
